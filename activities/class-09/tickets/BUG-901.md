# BUG-901 — Protect request detail by ownership

**Tipo:** reporte de seguridad · **Prioridad:** alta · **Estado inicial:** reported

## Reporte

> Un usuario autenticado con rol `requester` puede consultar solicitudes
> creadas por otros usuarios cambiando el ID en `GET /requests/:id`.

Reportado por el equipo de seguridad tras una revisión de rutina. Las
pruebas automatizadas existentes pasan: el hueco no está cubierto por
ninguna prueba. Eso también es parte del hallazgo.

## Objetivo

Corregir el acceso horizontal **sin alterar el contrato exitoso** para
usuarios autorizados.

## Reglas

* La ruta requiere autenticación (sin token → `401`).
* Un `requester` solo puede consultar solicitudes creadas por él.
* Un `agent` puede consultar cualquier solicitud.
* La identidad confiable proviene del **token verificado** — jamás de
  `userId`, `createdBy` o `assignedTo` enviados en query o body.
* Una solicitud inexistente devuelve `404`.
* Una solicitud existente pero **no visible** para el requester también
  devuelve `404` (ver decisión abajo).
* La respuesta autorizada conserva exactamente su schema anterior.
* **No** introducir una migración: el esquema no cambia.
* **No** crear capas nuevas: el módulo ya tiene route, service, policy,
  store y mapper.
* La regla debe vivir en una **policy comprobable sin Express** (pista:
  puede que ya exista — la pregunta es quién la consulta).
* Debe añadirse al menos una **prueba de regresión** que falle contra el
  bug y pase con la corrección.

## Decisión explícita de este sistema

> Se utiliza `404` tanto para inexistencia como para falta de visibilidad
> del requester. No es una regla universal (otros sistemas responden 403):
> es una decisión de ESTE sistema para no confirmar la existencia de
> recursos ajenos y reducir la enumeración de IDs. El historial
> (`GET /requests/:id/history`) ya la aplica — compara.

## Definición de terminado

* [ ] El bug se reprodujo ANTES de corregir (evidencia en el dossier).
* [ ] El análisis de impacto está completo y commiteado (`class-09-analysis`).
* [ ] requester ajeno → `404` · owner → `200` · agent → `200` · sin token → `401`.
* [ ] `userId` en query o body no concede acceso.
* [ ] El schema de la respuesta autorizada no cambió.
* [ ] La regla se prueba SIN Express ni base (`npm run test:policy`).
* [ ] La suite completa sigue verde y `npm run validate:class-09` termina en PASSED.
