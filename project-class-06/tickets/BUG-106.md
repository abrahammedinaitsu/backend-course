# BUG-106 — Empty filtered collection answers 404

Reported by: support team
Severity: medium
Status: open

## Symptom

When a valid collection filter has no matches, `GET /requests` returns `404`.

Steps to reproduce (with the workshop seed):

1. Log in as `ana.requester.seed@example.test`.
2. Request `GET /requests?status=closed` with her token.
3. Observe the response.

Ana has no closed requests, so the filter is valid and matches nothing.

## Expected behavior

A valid collection with no matches must return:

```http
200 OK
```

```json
[]
```

An empty collection is NOT a missing resource. `404` is for an individual
resource that does not exist (or must not be revealed) — see the class 3
contract for collections.

## Definition of done

1. `GET /requests?status=closed` (as Ana) answers `200` with `[]`.
2. The rest of the suite still passes.
3. A regression test pins the behavior so it cannot silently come back.
